# Earnings follow-up

## Establish the saved checks

Choose 3–7 prioritized observable questions, adjusted to the company's risks. Each needs a stable ID and criterion version; the reason it matters; sourced baseline with units, definition and period; what to look for; basis of the criterion; due period/date; and favorable/adverse/mixed/unresolved implications. Avoid generic “watch growth”. Identify the segment, share measure, cash requirement, credit cohort, margin or milestone.

Numerical thresholds need justification, not false precision. Distinguish management guidance, external estimate and our analytical test. Qualitative checks are valid when the evidence criterion is explicit. A missing baseline can be an unavailable record; explain that a trend cannot yet be compared.

Save the original item in the research ledger. The HTML and structured watchlist must be generated from that one record. Stable hashes catch accidental alteration; they do not authenticate the underlying disclosures.

## Reporting date

Consult the issuer's calendar/announcement first. Use Confirmed only for an official announced date; Estimated for a named provider or explained historical pattern; Not announced for unknown. Preserve the source and last schedule-check date even when unknown. Include reported financial period and separate results release, earnings call and regulatory filing events. Only display published time/timezone; distinguish any local conversion.

The report date is a checkpoint, not authorization for a reminder or background task. The user starts the next session. A copyable prompt includes ticker, exchange/share class, durable security ID and baseline report ID. An export includes the baseline chain, not just a screenshot or a prose recap.

## Return in a new session

1. Retrieve and verify the company archive and saved baseline through persistence.md. Never infer old thresholds from memory. Honor an explicit report ID; otherwise choose the latest applicable pre-release snapshot.
2. Recheck the schedule and confirm actual publication. A calendar date passing does not resolve the checks. If unpublished, report a pending state and preserve the original watchlist unchanged.
3. Read the issuer release and available applicable filing. Record whether a call/presentation/transcript was available and read. Mark provisional when missing materials affect interpretation. Do not wait for a pending transcript if useful release-based results can be assessed honestly.
4. Extract compatible actuals. Match GAAP/adjusted definitions, reported/constant-currency basis, YoY/QoQ periods, share denominator, business scope and fiscal duration. Read restatement notes; preserve the originally observed baseline and add a separate restated comparison.
5. Evaluate every saved watch ID before drafting replacements. Show original check → old value → new evidence → outcome → thesis impact. For a numeric rule use the saved operator and value without editing them.

| Outcome | Use when |
|---|---|
| Met | Comparable disclosed evidence satisfies the saved condition. |
| Missed | Comparable disclosed evidence fails it. |
| Mixed | A genuinely multi-part check has offsetting findings; explain each. Do not use it to avoid a clear scalar miss. |
| Not disclosed | Relevant material was read but the required disclosure is absent. Identify sources checked. |
| Not yet due | Relevant release is unpublished or a later milestone cannot yet be evaluated. |
| Not comparable | Definitions, scope, accounting or restatements prevent a valid comparison; explain why. |

An annual milestone is not missed merely because an intervening quarterly release does not resolve it. Missing disclosure alone is not an operating miss. Do not replace inconvenient original criteria with easier ones.

6. Assess the thesis as strengthened, weakened, broadly unchanged or unresolved. Treat price attractiveness separately. Refresh timestamped price and valuation if requested or materially affected; otherwise state that the update covers operating evidence, not a refreshed price conclusion.
7. Save a new dated snapshot linked to the original. Keep original expectations and outcomes immutable. New risks have their own list. Create the next watchlist/event separately; increment the version when changing a continuing item. Review reruns use the existing result unless new evidence warrants an explicitly superseding snapshot.

## Acceptance checks

Use the synthetic consecutive-period fixture and scripts/tests. Verify fresh-session retrieval, share-class isolation, ticker aliases, rescheduled dates, unpublished results, partial sources, exact-once outcomes, restatements, missing disclosures, later milestones and repeated-release detection. Persist the archive before claiming continuity is available.
